# Impeccable Design Context

## Design Context

### Users
Individual users managing their personal schedules, appointments, and email reminders. They expect a calendar app that is fast, reliable, and immediately familiar — no learning curve. The primary context is daily planning: quickly creating entries, scanning the week, and staying on top of reminders. Users may customize their experience with accent colors, language (EN/DE), and light/dark themes.

### Brand Personality
**Bold, modern, confident.** b-cal has opinions about how a calendar should work and isn't afraid to show them. The interface communicates competence through crisp execution rather than visual noise. It feels like a tool built by someone who cares deeply about the details.

### Aesthetic Direction
**Classic & professional with elevated craft.** Google Calendar is the primary reference — clean grid layouts, familiar calendar conventions, functional over flashy. But where Google Calendar is safe and utilitarian, b-cal should feel more intentional: sharper typography (Geist), more deliberate spacing, and confident use of the user's chosen accent color. The design should feel modern without being trendy.

- **Reference**: Google Calendar (layout conventions, information hierarchy, grid patterns)
- **Anti-pattern**: Overly playful or whimsical UIs that sacrifice clarity for personality; cluttered dashboards; skeuomorphic elements
- **Theme**: Light + Dark + System, with 6 user-selectable accent colors (blue, indigo, violet, emerald, amber, slate)
- **Color system**: OKLch color space for perceptual uniformity; 8 calendar entry colors for visual categorization

### Design Principles

1. **Familiar first, then better.** Follow established calendar UX patterns. Users shouldn't have to think about how the app works — but they should notice it feels better than what they're used to.

2. **Confidence through clarity.** Bold doesn't mean loud. Use strong typographic hierarchy, decisive spacing, and purposeful color to convey confidence. Every element should look like it was placed with intent.

3. **Respect the user's choices.** Accent colors, themes, and language preferences are first-class. Design decisions should amplify — never fight — the user's customization.

4. **Density without clutter.** Calendars are inherently information-dense. Embrace that density with clean alignment and consistent rhythm, rather than hiding information behind interactions.

5. **Accessible by default.** WCAG AA compliance as the baseline. Focus states, keyboard navigation, and semantic HTML are non-negotiable. The design should work for everyone without feeling like it's making accommodations.

### Technical Design Stack
- **CSS**: Tailwind CSS v4 with OKLch design tokens
- **Components**: shadcn/ui (new-york style) + Radix UI primitives
- **Typography**: Geist Sans (body) / Geist Mono (code)
- **Theming**: next-themes with class toggling, CSS custom properties
- **Variants**: class-variance-authority (CVA)
- **Icons**: lucide-react
- **Border radius**: 0.625rem base (rounded but not bubbly)
